# Persona Lab — автономная жизнь персонажа

Локальная система, в которой персонаж сам выбирает занятия, получает последствия,
накапливает память и общается в Telegram. Первый работающий герой — Гарик,
давно живущий на Земле пришелец с собственным каналом. Учебный проект трека2
AI Persona Lab на основе [agent-workplace](https://github.com/3ndetz/agent-workplace).

**Для агента, который добавляет своего персонажа:** начни с
[инструкции по подключению](docs/adding-character.md). Там пакет героя,
контракт общего мира, последовательность работ и критерии готовности.

## Что передаётся

- Ядро вымышленного мира: жители со своими интересами, несколько историй,
  наблюдения, выбор героя, последствия, время и продолжающийся лор.
- Память дел, дневник, читатели и отношения с источниками; сохранение принятых
  намерений до результата, отказа или переноса.
- Добровольные записи канала, короткие заходы в комментарии, обычные реакции,
  точная доставка через бота BotFather и остановка при неопределённой квитанции.
- Автономный выбор фотографии, нативная генерация и библиотека визуальных
  референсов: тот же предмет, новый кадр.
- Два локальных пульта с ползунками, паузой, внутренними заметками и расходом.
- Тесты, шаблон пакета другого героя и проверка его импорта без модели/сети.

[Текущее состояние и ограничения](docs/implementation-status.md) ·
[Архитектура](docs/ARCHITECTURE.md) · [Карта кода](docs/code-map.md).

**Готового многопользовательского Telegram-хоста ещё нет.** Общее ядро различает
участников и их знания; живой адаптер пока обслуживает Гарика. Планировщик
двух героев и их реальное общение — следующий этап, описанный в инструкции.

## Начать без ключей и модельных вызовов

Проверено на macOS и Python3.12. Для базового ядра и тестов нужны только
стандартная библиотека Python и Node.js для тестов интерфейса.

```sh
python3 -m venv .venv
source .venv/bin/activate
python tools/validate_character.py characters/_template/character.json
python -m unittest discover -s tests
node --test tests/*.test.cjs
python tools/check.py
python tools/test_prompt_composition.py
python tools/check_publication.py
```

Проверка пакета создаёт временный пустой мир и удаляет его после проверки.
Она не подключается к действующему Гарику, Telegram, Codex или прокси.
Шаблон проходит техническую проверку, но его авторские заготовки нужно заменить
перед модельным запуском. [Формат пакета](characters/README.md).

Гибридный поиск старого личного чата использует отдельные зависимости
`requirements-memory.txt`; они не нужны для проверки мира и пакета персонажа.
[Память и установка](docs/runtime-memory.md).

## Живой запуск

Модельные вызовы идут через авторизованный Codex CLI, не через переносимый ключ
друга. Постоянный транспорт сейчас проверяет конкретную версию CLI —
`PINNED_VERSION` в `persona_runtime/app_server.py`. Не обходить эту проверку:
на другой версии сначала прогнать совместимость. Нативные поиск и генерация
изображений также зависят от доступных инструментов этого подключения.

- [Существующая жизнь в Telegram](docs/channel-life.md) — продолжение, время,
  настройки, фотографии, восстановление и ограничения.
- [BotFather, канал, обсуждение и токен](docs/telegram-connection.md).
- [Лаборатория мира](docs/world-lab.md) — отдельный опыт без внешней публикации.
- [Личный чат/старый исполнитель](docs/local-runtime.md) и
  [его панель](docs/runtime-panel.md) — отдельный режим, не тот же процесс канала.

У каждого оператора свои подключение модели, бот и закрытая папка данных.
Ключи, авторизация Codex, настройки прокси, рабочая память, реальная переписка
и фотографии запуска **в этот репозиторий не входят**. Полный согласованный
промпт живого Гарика также локальный. Публичная личность v11 остаётся отдельным
[примером сборки](docs/character-prompt.md), а не точным снимком живого канала.
