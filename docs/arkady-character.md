# Аркадий: профиль, память и запуск

16 октября 2026. [Пакет Аркадия](../characters/arkady/README.md) подключён
к лаборатории и отдельному Telegram-хосту через `--profile`. Ветка
`feat/arkady-character-package`; исходный перенос — коммит `75d4395`.

## Что поддерживается

- Личность, канон, речь и восемь собственных стартовых сущностей.
- Восемь авторских воспоминаний: жизнь до знакомства, передатчик, контакт,
  дружба с Гариком, работа над телом, цифровая копия, контейнер и мастерская.
  Они хранятся в восьми тематических записях с `provenance=author_backstory`.
- Три исходных интереса: непрерывность личности, дружба и обычная жизнь.
  Дальнейший опыт, записи, намерения и последствия сохраняются в SQLite.
- Реальные комментарии, отдельная память читателей с источниками,
  собственные обещания, реакции и подтверждения доставки.
- Свой actor_id в каждом этапе, восстановлении памяти и фото; собственная
  визуальная библиотека. Можно подключить портреты/референсы через пакет.
- Пульты с именем Аркадия, авторской предысторией, личными делами,
  событиями, расходом и доставками; отдельные папки и настраиваемые порты.
- Продолжение существующего запуска без повторного импорта памяти.
  Изменённый пакет и чужая папка данных требуют явной миграции.

## Текущая авторская редакция

Аркадий **Кедров** стал более любопытным, тёплым и живым. Он любит обычные
дела, людей, небольшие удачи; страх смерти и споры с копией не поглощают
каждый разговор. Упрямство, инженерный азарт, ошибки и прежняя история
сохранены. Самостоятельные файлы характера, жизни, речи и примеров —
[в пакете](../characters/arkady/README.md). Они загружаются явно через
`persona_sections`; личность и словари Гарика не подмешиваются.

Дополнительно по просьбе автора: бытовая самоирония, озорство, редкие смешные
вспышки досады («ёк-макарёк», «ядрён батон»). Это возможность, а не обязательный
элемент реплики. Образцы не создают события, факты и воспоминания.

В одиночном Telegram-хосте долгое занятие больше не перекрывает собственный
канал: во время ожидания он может отдельно решить, хочет ли поделиться мыслью,
или вернуться к обещанному посту. Проверки ограничены темпом `wake_minutes`
и сохраняются при перезапуске; пост остаётся добровольным. Ответы читателям
сохраняют отдельные заходы. Будущий outcome скрыт от всех таких решений,
срок и результат принятого действия не меняются и не вычисляются повторно.
В Telegram-пульте видны начатое действие и оставшиеся минуты: отсутствие
новых вызовов во время физического ожидания само по себе не означает зависание.

Модель Аркадия: **`gpt-6-luna`**, reasoning **`low`** (минимальный).
Настройка `runtime` находится в `characters/arkady/character.json`,
применяется в лаборатории и Telegram-хосте ко всем модельным службам.
Другие герои сохраняют свои настройки. Неизвестная/недоступная модель
вызывает явную ошибку, автоматической замены нет. В `/api/state` пульта мира
видны `model` и `reasoning_effort`. Режим `none` проверен отдельно: речь работала с нулём reasoning-токенов,
но полный эпизод нарушил контракт внутренней роли мира. Поэтому выбран
`low`; проверки результатов остаются строгими.

Основа — исходный `agent/resources/arkadiy.md`, переработанный по просьбе
автора 16 октября 2026. Фамилия Кедров теперь установлена автором. Не заданы
точная сцена/дата знакомства, анализ крови, имя копии «Дубль», заказ
сервоприводов, содержимое контейнера и готовность стенда. Исходный проект
не меняется. Примеры не становятся событиями, перепиской или результатами.

## Подготовка

Из корня `ai-persona(KIRILL)`:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
mkdir -p .local
python tools/validate_character.py characters/arkady/character.json
```

Для офлайн-режима нужны Python 3.12 и его стандартная библиотека.
Дополнительные зависимости embeddings не нужны. На машине разработки
`.venv` уже создана; системный `python3` указывает на 3.9.6.

## Лаборатория без модели

```sh
./start-arkady.command lab
```

Открыть `http://127.0.0.1:8866`. Данные — `.local/arkady-lab/`.
Профиль и стартовая память импортируются автоматически, вызовы модели
и Telegram выключены. Ctrl+C останавливает только этот процесс.

Для конечного модельного просмотра:

```sh
./start-arkady.command lab --live --max-calls 12
```

Модельные этапы выполняются вручную из пульта. Нужны собственная
авторизация Codex и настроенный транспорт; текущий `world_lab --live`
по умолчанию требует включённого прокси. При доступном прямом соединении
можно явно добавить `--allow-direct`; при ошибке настроенного прокси
автоматического перехода на прямое соединение нет.
CLI закреплён на `0.162.0-alpha.17.2`
в `persona_runtime/app_server.py`. Эта версия уже установлена на машине
разработки. Настройки подключения — [proxy/локальный запуск](local-runtime.md).
Для новой версии CLI сначала проверяют совместимость, ограничитель
версии не удаляют. Поиск доступен при явном `--research`.

Параметры режима подготовленного эпизода должны совпадать при продолжении.
Команда-обёртка задаёт одинаковые флаги лаборатории с моделью и без неё.
Ошибка или прерванный этап сохраняются, автоматически не повторяются.

## Telegram

Нужны собственный бот из BotFather, канал, связанная группа обсуждения
и права администратора бота. Токен вводится только в локальном пульте.
[Подробная настройка Telegram](telegram-connection.md).

1. Остановить лабораторию, если она занимает порт 8866.
2. Запустить настройку:

   ```sh
   ./start-arkady.command setup
   ```

   Открыть `http://127.0.0.1:8867`, ввести токен своего бота и привязать канал.
   После настройки остановить этот сервер через Ctrl+C: живой хост сам
   откроет это подключение и пульт. Настройка Telegram сама не требует модели.

3. Запустить собственную жизнь:

   ```sh
   ./start-arkady.command live --start
   ```

   Пульт мира — `http://127.0.0.1:8866`, Telegram — `http://127.0.0.1:8867`.
   Данные жизни — `.local/arkady-life/`, секреты и курсор —
   `.local/arkady-telegram/`. Лаборатория и жизнь используют разные базы.
   Без `--start` новая жизнь открывается на паузе; продолжить можно в пульте.
   Настоящие модельные вызовы и публикации начинаются после запуска жизни.

Обёртка добавляет `--fresh` только пока жизнь не инициализирована.
Повторный обычный запуск продолжает сохранённый мир, не очищает историю,
память, читателей и намерения. Для уже начатой жизни нельзя вручную
добавлять `--fresh`. Изменение personality, канона, memory.json или среды
после импорта требует отдельной миграции, а не замены прожитого состояния.
README и другой сопроводительный текст не входят в fingerprint профиля.

При неопределённой доставке жизнь остановится. Не повторять отправку
вслепую: проверить канал и использовать явный разбор доставки в пульте.
Ctrl+C сохраняет данные. Секреты, базы и фото остаются в игнорируемой `.local/`.

### Перенос уже прожитой лаборатории

Для продолжения существующего мира не использовать `--fresh` поверх истории.
Остановить планировщик, дождаться завершения текущего эпизода и idle,
затем штатно остановить лабораторию и экран настройки Telegram. Сохранить
SQLite-backup мира и подключения с `PRAGMA integrity_check`.

Копия базы мира переносится в новую папку жизни без изменения событий,
вызовов, заметок, интересов и авторской памяти. Отдельная операция
`activate_existing_world(store, connection, actor_id=profile.actor_id)`
в `channel_life.py` включает Telegram только в остановленном мире без
незавершённых этапов. Время мира сохраняется и привязывается к реальному
ходу часов с момента переключения. Повторная активация блокируется.

Прежние локальные черновики сохраняются с заданиями `local_only`, без
квитанций отправки. Хост не выгружает их в канал автоматически и не
объявляет доставленными. Новые публикации выбирает сам персонаж.
Исходная лаборатория и резервная копия остаются отдельно; дальнейший
обычный запуск обёртки продолжает папку `.local/arkady-life/`.

Альтернативная команда с явными портами и папками:

```sh
.venv/bin/python -m persona_runtime.channel_life \
  --profile characters/arkady/character.json \
  --data-dir .local/arkady-life --telegram-dir .local/arkady-telegram \
  --world-port 8866 --telegram-port 8867 --start
```

При самом первом прямом запуске добавить `--fresh`. `--no-photos` выключает
фото и сохраняет эту настройку; включить их снова можно в пульте.
`--background` запускает в фоне и возвращает адреса/pid. `--awake-hours 0`
на macOS удерживает компьютер от сна, пока работает процесс.

## Файлы и память

`memory.json` — исходная авторская память, не живая база. У каждой записи
свой actor-scoped id и provenance; исходные личные дела ссылаются на неё.
При первом импорте записи попадают в `world_memories`, интересы —
в `world_concerns`. Они не создают вымышленную свежую историю или вызовы.

Модель получает только собственные воспоминания и свои личные записи.
Мир получает краткий внешний канон, наблюдаемые события и краткую подсказку
интереса, без чужой частной памяти. Память читателей хранится отдельно
в `reader_people`/`reader_facts`, обещания — в `personal_intentions`.
Выполнение поступка подтверждает outcome, публикации — sent-квитанция;
авторское воспоминание не может подменить ни то, ни другое.

Для утверждённых изображений можно добавить в manifest необязательный
путь `visual_references` к JSON вида `{"arkady": "portrait.png"}` или
`{"arkady_transmitter": "transmitter.png"}`. Файлы должны лежать внутри
пакета. Байты участвуют в fingerprint, абсолютные пути не публикуются.
Сейчас утверждённого портрета Аркадия нет; фото доступных вещей работают
без него. Контекст фото и библиотека выбираются по настоящему actor_id.

## Явное обновление существующего профиля

Сохранить предыдущий пакет в игнорируемой `.local/`, затем подготовить
новый. Поставить жизнь на паузу, дождаться idle и штатно завершить процесс.
Операция требует эксклюзивного владения миром и создаёт SQLite-backup
с `integrity_check` до изменений:

```sh
.venv/bin/python -m persona_runtime.profile_update \
  --data-dir .local/arkady-life \
  --previous .local/arkady-previous/character.json \
  --profile characters/arkady/character.json \
  --backup-dir .local/backups/arkady-author-revision \
  --reason 'Авторская редакция характера и модели'
./start-arkady.command live --background
```

`--previous` должен точно совпадать с установленным fingerprint. Операция
меняет авторские материалы, имя и модель, сохраняет журнал старой/новой
редакции. Дополняет исходную память без удаления прожитой; текущие интересы
не переинициализирует. Среда и визуальные референсы этой операцией не меняются.
Единственное допустимое незавершённое дело — уже принятое физическое действие
с сохранённым outcome в ожидании experience: результат, срок и входы остаются
прежними, новые этапы получают новую личность. Running/blocked и незавершённый
речевой заход не обходятся. Никакие вызовы и доставки не повторяются.

После проверки состояния жизнь можно продолжить кнопкой пульта. При
неизвестной доставке сначала проверить наличие сообщения в Telegram и
выполнить явный разбор; смена профиля не снимает эту блокировку.

## Проверки и границы

На новой модели выполнены закрытые пробы речи и полный отдельный эпизод
(world → impulse → choice → outcome → experience → share) на временной базе,
без Telegram. `gpt-6-luna / low` прошла все шесть этапов и проверку результата.
Это ограниченная проверка совместимости, а не гарантия художественного качества.
Фактический голос автор оценивает по дальнейшему общению.

Проверено 16 октября: **377 Python-тестов и 32 UI-теста прошли**,
включая 12 сценариев профиля/хоста и 3 проверки перехода из лаборатории.
Четыре дополнительных проверки покрывают ответы во время долгого дела,
недоступность будущего результата, продолжение после перезапуска и запрет
скрытого обхода чужой revision. Комментарии не сдвигают срок собственного дела.
Дополнительно прошли 9 проверок
сборки промптов, проверки файловых рабочих мест, валидация Аркадия
и неизменённого шаблона. Аудит 266 текстовых файлов не обнаружил секретов
или запрещённых рабочих данных.

```sh
.venv/bin/python -m unittest discover -s tests
node --test tests/*.test.cjs
.venv/bin/python tools/check.py
.venv/bin/python tools/test_prompt_composition.py
.venv/bin/python tools/check_publication.py
git diff --check
```

Папка `.local` нужна двум прежним тестам речи; создать её перед полным
прогоном. Новые проверки включают запуск HTTP-лаборатории без модели,
сборку живого CLI с подставными сервисами, импорт/изоляцию предыстории,
пост, комментарий, память читателя, обещание и восстановление после остановки,
блокировку неизвестной доставки, собственный фото-контекст и UI профиля.

Офлайн-тесты не выполняют внешних модельных вызовов и настоящих публикаций.
Рабочий Гарик не перезапускается. Прогоны самого оператора хранятся отдельно
в `.local/`, без публикации баз и переписок. Художественный голос нужно оценить автору
на новых многоходовых ситуациях: отказ, просьба без мата, забота, сбой
устройства и возврат к незавершённой затее.

Хост обслуживает один профиль в отдельном мире и один Telegram-бот.
Совместная жизнь Аркадия и Гарика в одной базе требует общего планировщика
с независимыми ожиданиями и внутренней доставки реплик; это отдельный этап.
Другой подключённый герой не управляется как NPC. Старый личный
чат `python -m persona_runtime chat` остаётся отдельным исполнителем Гарика;
для Аркадия использовать команды профиля выше.

## Общий мир с Гариком

Теперь есть отдельный центральный хост: [совместная жизнь](shared-life.md).
Одиночный запуск Аркадия автоматически не превращается в общий. Перенос
сохраняет обе истории, требует данных Гарика, паузы, idle и штатной остановки
прежних владельцев. `start-shared.command` использует отдельную конфигурацию
и порты 8886/8887/8888, не второй процесс над одиночной базой Аркадия.
