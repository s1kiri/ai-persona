# Разбор agent-workplace

Проверено 7 октября 2026. Основа: upstream `fc5f293`.

## Что это

Это рабочие файлы персонажа и небольшой набор утилит на Python и Bash.
В шаблоне нет сервера приложения, зависимостей LLM-провайдера и бесконечного
цикла. Его удобно использовать для разных сред, включая неигровые.

## Где что находится

| Файл или папка | Роль |
| --- | --- |
| `AGENTS.md` | Контекст проекта и инструкции помощнику, который пишет код |
| `agent/AGENTS.md` | Инструкция самому персонажу во время сессии |
| `agent/vesper/PERSONA.md` | Демонстрационная личность |
| `agent/vesper/GOALS.md` | Текущие цели персонажа |
| `agent/vesper/SESSION_PROMPT.md` | Задача на каждую сессию |
| `agent/vesper/memory/state.md` | Короткое состояние между сессиями |
| `agent/vesper/memory/entities/` | Заметки о людях и местах |
| `agent/vesper/inbox.jsonl`, `outbox.jsonl` | Входящие сообщения и очередь ответов |
| `agent/shared/rules.md` | Общие правила поведения |
| `tools/compose_session.py` | Собирает данные в текст промпта |
| `tools/check.py` | Проверяет целостность файлов примера |

## Что делают инструменты

- `say.sh <recipient> <text>` дописывает JSON в outbox. Ничего не отправляет в сеть.
- `remember.sh <entity> <text>` добавляет датированную запись в заметку сущности.
- `sleep.sh <minutes>` записывает число в файл. Сам ничего не ждёт и не запускает.
- `ticket.sh <text>` сохраняет локальную заявку в `tickets/`.

Скрипты рассчитаны на запуск из корня. Персонаж задаётся переменной `AGENT_NAME`,
по умолчанию это `vesper`. Эти скрипты при разборе прочитаны, но не запускались,
чтобы сохранить демонстрационные данные в исходном виде.

## Проверено на этом компьютере

```sh
python3 tools/check.py
python3 tools/compose_session.py vesper
```

Обе команды завершились успешно. Проверка нашла Vesper и подтвердила наличие
нужных файлов, разрешимость ссылок памяти и корректный JSON. Сборщик вывел
промпт размером 12 425 байт на момент проверки. Модель не вызывалась, токены не тратились.

## Ограничения, важные перед реальным запуском

1. **Нет исполнителя.** Нужно подключить вызов модели, выполнение разрешённых
   действий, обработку результата и следующий запуск. Текст промпта сам этого не делает.
2. **Ответ в очереди считается ответом человеку.** `unanswered()` смотрит на
   время последней записи в outbox, хотя доставка могла не состояться. Для
   интеграции нужны отдельные статусы отправки и идентификаторы сообщений.
3. **Однократность инструкций пока только описана.** Параметр `--from-operator`
   просто вставляет текст. За то, что инструкция передана один раз и не потеряна
   при сбое, должен отвечать будущий исполнитель.
4. **Изоляция пока является правилом в тексте.** В именах персонажей/сущностей
   не проверяется выход за пределы папки через `..`; скрипты не создают песочницу.
   Перед выдачей инструментов автономной модели нужны проверки путей и реальные права.
5. **Ожидание не валидируется.** `sleep.sh` сохраняет произвольный аргумент.
   Будущий цикл должен ограничивать интервалы, частоту запросов и расходы.
6. **Проверка структуры не проверяет поведение.** `check.py` не доказывает качество
   личности, доставку сообщений, права доступа, корректность полей JSON или автономность.

Это список задач интеграции, а не повод заранее переписывать весь шаблон.

## Возможный этап после подготовки репозитория

После отдельного поручения Кирилла: подключить одну модель к собранному контексту
и получить ответ в терминале. Текущая задача ограничена подготовкой и публикацией
репозитория для первой домашней работы.
До этого выбрать способ доступа к модели и допустимый бюджет. На первом этапе
ответ только показывается человеку; инструменты и автоматическую публикацию
подключать отдельными проверяемыми шагами.

Если позже выберем контентный проект, возможная цепочка: идея → сценарий →
материалы → сборка ролика → просмотр → публикация → обратная связь. Это гипотеза
будущего продукта. Пока у нас нет ни выбранной ниши, ни интеграций, ни проверки спроса.

## Git и публикация

История организаторов сохранена. `upstream` указывает на
`https://github.com/3ndetz/agent-workplace.git`. Собственного `origin` пока нет.
Изменения подготовки сохранены отдельным коммитом. Перед публикацией нужно
создать/выбрать свой репозиторий и добавить его как origin. Атрибуция шаблона сохранена.
Вымышленные inbox/outbox Vesper входят в оригинальный пример; после подключения
живых людей рабочие диалоги необходимо хранить отдельно от публичного кода.
