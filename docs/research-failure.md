# Неудачный поиск в общем мире

Необязательный поиск не должен останавливать всю жизнь персонажа. Если отдельный
research-процесс завершился с CodexError, общий планировщик сохраняет исходный
неудачный вызов и usage, затем переводит эпизод к последствиям неудачной попытки.
Окно действия и его срок сохраняются. Поиск повторно не вызывается; факты,
источники и успешный результат не придумываются. Outcome обязан иметь status=failed.
Персонаж самостоятельно выбирает реакцию и дальнейшие дела.

Автоматический переход не применяется к отмене вызова, остановке персонажа,
ошибке валидации или неизвестной доставке. Такие случаи требуют прежнего разбора.
Явное восстановление уже заблокированного поиска журналируется отдельно, при
отсутствии активных вызовов; исходная ошибка не стирается.

Транспорт сохраняет безопасный код причины, число обнаруженных web-вызовов и
завершённые квитанции по мере поступления. Сырые исключения, аргументы инструментов
и внутренние рассуждения в эту диагностику не копируются. Ограничение на два
нативных web-вызова за попытку осталось прежним.

16 октября восстановлена одна заблокированная попытка рабочего запуска без
повтора поиска. Её старые логи не сохранили точную причину CodexError; гипотеза
о лимите web-вызовов не считается установленным диагнозом. Восстановление жизни
после сбоя само по себе не подтверждает успешность следующего поиска.

Проверки на временных данных: сохранение исходного вызова и окна, отсутствие
повтора, запрет успешного outcome, сохранение остановки при отмене, диагностика
отсутствующей квитанции и превышения лимита web-вызовов.
