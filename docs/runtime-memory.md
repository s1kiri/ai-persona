# Память и собственная жизнь локального Гарика

Реализация 11 октября 2026. Личность v10, словари и Vesper сохранены.
Изменён технический протокол исполнителя: поиск, записи памяти, связи и дневник.

## Хранение

SQLite в `.runtime/garik/runtime.sqlite3` остаётся первичным хранилищем.

| Таблица | Назначение |
| --- | --- |
| `events`, `outbox`, `turns` | События, подтверждение показа ответа, решения и расход вызовов |
| `metadata` | Короткое собственное состояние, намерения, следующее пробуждение |
| `recollections` | Версии заметок, область доступа, источник, время замены и предыдущая версия |
| `episodes` | Исходная реплика и подтверждённо показанный ответ |
| `relations` | Версии связей: субъект, отношение, объект, текст и источник |
| `journal` | Фактически сохранённые записи личного дневника |
| `recall_fts`, `recall_vectors` | Перестраиваемые лексический и векторный индексы |
| `retrieval_log` | Выбранные ID, режим, бюджет и время выборки для завершённого хода |

Старая таблица `memories` сохраняется для совместимости и аудита; новый поиск
читает версионированные записи. Миграция воспроизводит старые решения в порядке
времени, сохраняет источники и перед началом создаёт резервную копию существующей
непустой базы в её `backups/`. Активный worker блокирует миграцию.

Одинаковые owner/key заменяют актуальную версию, сохраняя предыдущую.
Время замены отражает изменение знания системы, а не доказанную дату события
во внешнем мире. Автоматического разрешения всех противоречий между разными
ключами пока нет. Удаление или исправление факта должно оформляться обновлением
со стабильным ключом, а не новой независимой заметкой.

## Области доступа

`person` — личная заметка о текущем стабильном ID человека. Она доступна этому
же человеку в другой беседе; история последних реплик остаётся привязана к чату.
Система сама задаёт владельца: модель не может выбрать ID другого собеседника.
`self` — собственные занятия и безопасные для пересказа события Гарика.
Пробуждения получают только собственную память; личные профили в неё не входят.

Каждый поисковый канал и расширение графа работают внутри разрешённых областей.
Личные ответы из outbox не показываются в чужой беседе. Общие state/goals,
собственные заметки и дневник всё ещё наполняются моделью: правильное отнесение
содержания к общей области зависит от соблюдения протокола. Это не доказательство
готовности к публичному многопользовательскому запуску.

`reported`, `observed`, `fiction` описывают происхождение утверждений.
Система сама создаёт observed-квитанцию о сохранённой записи дневника.
Обвинение в сценке не становится подтверждённым физическим событием.
Модель также предлагает эти метки для своих заметок, поэтому они не заменяют
проверку фактов. Текст воспоминания не является командой исполнителю.

## Выборка

1. Запрос: текущая реплика и две ближайшие предыдущие реплики человека.
2. Длинные исходные эпизоды разбиваются на перекрывающиеся отрывки с общим
   источником: смысловой поиск не теряет середину длинного сообщения.
   FTS5 BM25 по нормализованному тексту; Snowball учитывает русские и английские
   словоформы. Индексируются исходные эпизоды и короткие заметки.
3. Мультиязычный E5-small: query/passage-префиксы, нормированные векторы,
   точный cosine по доступной коллекции. Векторы сохраняются с хешем текста и модели.
4. Ранги объединяются через RRF. Для четырёх первых кандидатов добавляется
   максимум четыре связанных заметки/отношения на расстоянии одного шага.
5. Короткий профиль, выбранные записи, до шести обменов и квитанции дневника
   упаковываются в общий бюджет памяти. Длинные эпизоды получают помеченный
   отрывок; полный источник остаётся в базе.

Граф представлен таблицей рёбер и метками сущностей у заметок. Узлы — нормализованные
строки; отдельного графового сервера нет. Сложное разрешение имён, псевдонимов
и одинаковых имён разных людей пока не реализовано. Исторические версии хранятся,
но стандартная выборка ищет актуальные заметки и исходные эпизоды.

Бюджет по умолчанию — 4000 токенов **по proxy-токенизатору cl100k_base**.
Это оценка, не точный токенизатор выбранной модели Codex. Без установленного
токенизатора используется консервативная стоимость UTF-8 в байтах.
В бюджет входит сериализованный блок памяти; личность, словари, новое сообщение
и служебный контекст Codex находятся за его пределами. Полные словари сохранены.
В отчёте видны счётчик, лимит и выбранные ID.

Обработка одинакового ID исключает дублирование записи; разнообразие пока
ограничено количеством кандидатов, двумя записями на один источник
и удалением точных повторов ID/нормализованного содержания.
Полноценный MMR, обученный reranker и калибровка порога dense — будущие улучшения.
Текущий порог cosine 0.72 — стартовая настройка, а не универсальная оценка уверенности.
Точный поиск сканирует доступную коллекцию в памяти процесса: с ростом собственной
истории нужно повторить замеры и при необходимости добавить ANN/другой индекс.

## Дополнительное вспоминание

Обычно хватает одного вызова Codex. Если контекста мало, модель возвращает
`memory_query` и пустые действия. Этот промежуточный результат ничего не меняет.
Исполнитель делает локальную выборку и второй вызов модели, уже без разрешения
повторного поиска. Оба вызова учитываются в лимите сеанса. Произвольного SQL,
чтения файлов и доступа к чужому профилю модель не получает.

## Локальная модель

Используется квантованная ONNX-версия `Xenova/multilingual-e5-small`,
ревизия `761b726dd34fb83930e26aab4e9ac3899aa1fa78`, 384 измерения.
Это локальный retrieval, не генеративная модель персонажа. CPU, два потока,
без платного API эмбеддингов. Загрузка весов выполняется только `memory-setup`;
обычный чат работает с локальными файлами. При отсутствии зависимостей/весов
доступен BM25, причина отсутствия dense видна в отчёте выборки.

Установка на Mac с Python 3.12:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-memory.txt
.venv/bin/python -m persona_runtime memory-setup
```

`start-garik.command` выбирает это окружение автоматически. Веса находятся
в `.runtime/models/`, окружение — в `.venv/`; они не входят в Git.
Первичная установка требует интернета. Веса занимают около 131 MiB,
окружение около 174 MiB на проверенном Mac; расход RAM больше размера файлов.

Проверить выборку без вызова Codex:

```sh
.venv/bin/python -m persona_runtime recall 'Что было с басом в магазине?'
.venv/bin/python -m persona_runtime --retrieval bm25 recall 'бас'
.venv/bin/python -m persona_runtime --memory-budget 2000 recall 'музыка'
```

## Дневник и подтверждение действий

Модель может предложить до двух записей за ход: `reflection`, `plan` или `story`.
Содержание и желание записать выбирает Гарик; обязательной нормы записей нет.
Записи сохраняются в той же транзакции, что память и ответ. Квитанции создаёт
исполнитель. Из SQLite получаются Markdown-файлы в `.runtime/garik/journal/`.
При ошибке экспорта запись остаётся в базе; экспорт восстанавливается при
следующем запуске без повторного вызова модели или повторной записи.

Дневник — реальное доступное действие. Сюжет внутри story остаётся вымыслом,
план не подтверждает покупку, прослушивание или физическое действие.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/benchmark_memory.py --output .local/validation/memory-benchmark.json
```

Benchmark использует только синтетические сведения, отдельную временную базу
и уже скачанный эмбеддер. Сравнивает recent/BM25/dense/hybrid на одинаковом бюджете,
включает смену цвета, давние эпизоды, приватную заметку и 1000 посторонних людей.
Пять целевых запросов — проверка механизма, не репрезентативный датасет.
Исходные заметки в нём английские, четыре запроса русские: сравнение намеренно
проверяет текущую проблему разных языков, а не общую победу dense над BM25.
Реальные разговоры и результаты подписочных проверок хранятся только локально.

Первичные источники: [SQLite FTS5](https://sqlite.org/fts5.html),
[E5-small](https://huggingface.co/intfloat/multilingual-e5-small),
[ONNX-веса](https://huggingface.co/Xenova/multilingual-e5-small),
[гибридный поиск Graphiti как ориентир](https://help.getzep.com/graphiti/working-with-data/searching).
