# Зависание локальной SQLite · 16 октября2026

В11:59 МСК world-этап остался started. Сигнал сопровождения в12:33 обнаружил
отсутствие продвижения больше34 минут. Это не ожидание длительности outcome:
цикл находился в world без сохранённого результата, UI формально running.

## Наблюдение

Процесс жизни был жив и занимал100% одного ядра. Короткий macOS sample
показал рабочий поток внутри системной libsqlite3.dylib:
sqlite3_reset → sqlite3VdbeReset → sqlite3_db_release_memory →
purgeableCacheShrink → mach_vm_purgable_control. Python был Apple CLT3.9.6,
SQLite3.51.0. Проблемное ожидание происходило в native-коде базы, поэтому
таймер обработки модельного ответа не обеспечивал остановку этого участка.
Вход world сохранён; результат/usage в базе не появились. Завершение
модельной части этой попытки считается неизвестным, расход не объявляется нулём.

Профиль устанавливает место зависания, но не его первопричину внутри
SQLite/macOS. Это не доказанный сбой OpenAI, сети или авторизации.
При проверке протокола использована официальная документация
[Codex App Server](https://learn.chatgpt.com/docs/app-server): успешное
завершение требует соответствующего завершённого turn, а не живого процесса.

## Восстановление

На установленном .venv Python3.12.10 используется независимая Homebrew
SQLite3.53.3, не системная библиотека Apple. Сначала сделаны согласованные
копии обеих рабочих баз; integrity_check=ok. На отдельной копии100 циклов
state/actor_view/snapshot прошли за0.27 секунды. Общая офлайн-серия на этом
интерпретаторе:382 теста, OK; ещё2 теста выбора интерпретатора прошли отдельно.

SIGTERM не завершил зависший процесс за8 секунд, потребовался SIGKILL.
До/после остановки сохранены отдельные snapshots обеих баз. WorldStore
пометил started как interrupted; оператор abandon снял только этот цикл
без результата. Исходный вход, попытка и её сохранённый usage остаются.
Все прежние world_events и completed usage сравнены до/после и совпали.
Новых событий за прерванный цикл не сочинено, доставки не повторялись.
Решение записано в operator_episode_recovery с completion_unknown=true.

Жизнь запущена из .venv без fresh и сброса памяти. Личность, защита роли,
lively_world, готовность постить55 и постоянный запрет сна сохранены.
Следующий цикл новый, со своим входом и временем; старый не возобновляется.

В live entry point добавлена защита от случайного повторного запуска через
Apple CLT Python: если готовая .venv существует, процесс до открытия баз
перевыполняется через неё. Если её нет, запуск прекращается с ошибкой.
Другие платформы/интерпретаторы не перенаправляются. live.json теперь хранит
путь Python и версию SQLite. Долгосрочное отсутствие повторов native-сбоя
ещё не доказано; точная причина в системной библиотеке не установлена.
