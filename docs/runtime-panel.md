# Фоновый Гарик и локальная панель

Из корня проекта на Mac с настроенным Codex и локальным Python-окружением:

```sh
./start-garik.command daemon start
./start-garik.command panel
./start-garik.command daemon status
./start-garik.command daemon stop
```

Если команда `garik` уже настроена, те же действия: `garik daemon start`,
`garik panel`, `garik daemon status`, `garik daemon stop`.
Панель открывается в Microsoft Edge: http://127.0.0.1:8765.
`panel` запускает daemon, если он ещё не работает. Повторный start не создаёт
второго владельца базы. Состояние и переписка по умолчанию в игнорируемой
`.runtime/garik`; тесты всегда используют отдельные базы.

## Жизнь вне вкладки

Процесс Python отделён от Terminal и браузера. Закрытие вкладки не останавливает
ожидания, генерацию или доставку в локальный чат. Открытая вкладка получает
сохранённые сообщения и наблюдаемые события; просмотр отмечается отдельно.
Генерация идёт в отдельном потоке, SQLite имеет одного владельца. Каждая
отправка имеет UUID: повтор после обрыва связи не создаёт второй вызов.
Новая реплика отменяет устаревший ответ и недоставленные продолжения.
Раздельные сообщения приходят с выбранными персонажем паузами.

Пауза инициативы сохраняется в базе; общаться при ней можно. Кнопка отмены
прерывает текущий ответ. Остановка завершает модельный процесс и daemon;
память и чат сохраняются. При аварийной смерти Python специальный supervisor
останавливает группу дочернего Codex. При новом старте прерванные попытки
помечаются, события восстанавливаются с существующим пределом повторов.
Браузер сам не создаёт пробуждения или модельные запросы.

Mac должен бодрствовать. Сон приостанавливает выполнение; код не меняет
настройки сна и не запускает caffeinate. Автозапуск при входе не включён.
`garik daemon autostart-template` лишь создаёт приватный шаблон
`.local/garik.launchagent.plist` с RunAtLoad=false/KeepAlive=false;
его установка требует отдельного решения пользователя.

## Ограниченный запуск

Стандарт: 20 попыток Codex, 3 самостоятельных пробуждения за 60 минут,
минимальный интервал пробуждений 300 секунд. Новые вызовы прекращаются
после 500000 известных input+output токенов за запуск, 100 попыток или
1000000 известных токенов за день UTC. Дополнительный recall/search тоже
расходует попытки. Ограничение токенов post-hoc: один уже начатый запрос
может превысить порог, неизвестный usage нельзя считать нулём.
После исчерпания лимита HTTP-панель остаётся доступна, новые реплики
сохраняются без генерации. Новый запуск обновляет сеансовый предел,
дневной учёт сохраняется. Лимиты уже работающего процесса повторным start
не меняются: сначала status/stop, затем start с нужными параметрами.

```sh
garik daemon start --max-calls 12 --max-wakes 2 --max-minutes 30
garik daemon start --no-autonomy --max-calls 6
```

Для отдельной базы из корня проекта:

```sh
.venv/bin/python -m persona_runtime --data-dir .local/panel-demo daemon start --port 8766 --no-autonomy
.venv/bin/python -m persona_runtime --data-dir .local/panel-demo daemon status
.venv/bin/python -m persona_runtime --data-dir .local/panel-demo daemon stop
```

## Что показывает панель

Жизнь/чат: текущее занятие и следующий шаг, действительное следующее
пробуждение с учётом минимального интервала, процесс, очередь частей сообщения,
наблюдаемые стадии native web и ошибки. Это не поток внутренних рассуждений.
Каналы: реально доступен локальный чат, память и разрешённый native web;
Telegram и голос не подключены. Telegram остаётся отдельной задачей:
бот или API аккаунта здесь не выбираются и не подключаются.

Usage: точные значения из native JSONL `turn.completed` Codex приходят
после завершения, ступенями. Вход, выход, cached input, cache write и reasoning
сохраняются, если CLI их предоставил. Кэш — часть input, повторно не прибавляется.
Таблица хранит попытку, категорию chat/wake/recall/search, выбранную модель
или неизвестную, статус и usage. Суммы есть за запуск, день UTC и историю.
Это расход данного Гарика, не лимит всего ChatGPT-аккаунта и не стоимость.
Отсутствующее поле показано «—», частичный итог — нижняя граница.
Старые завершённые ходы импортируются как агрегаты без двойного счёта
включённых попыток; неизвестное количество старых вызовов остаётся неизвестным.

Квитанция usage пишется в приватный fsync-журнал до декодирования решения:
известный расход сохраняется и при ошибке, отмене или перезапуске. Повторное
чтение журнала идемпотентно; оборванный последний фрагмент чинится при старте.
Если сам CLI не успел выдать usage, точную цену такого запроса мы не знаем.

Контекст: локальная оценка объёмов личности/контракта/реплики/состояния/
истории/памяти/занятий/источников, бюджет памяти, сокращение истории и
происхождение выбранных записей. Это не точный токенизатор удалённой модели,
не её полный внутренний контекст; инструкции CLI и результаты native web
в оценку не входят. Текст приватного состояния и рассуждения не показываются.

## Локальная защита и данные

HTTP слушает только 127.0.0.1. Проверяются Host/Origin, session cookie
HTTPOnly/SameSite=Strict и CSRF для изменений. Нет CORS, внешних шрифтов,
CDN или исполняемого HTML из ответов. Управляющий токен живёт только в файле
0600, не URL; CLI обходит inherited HTTP proxies только для своего localhost
control-запроса. Модельный транспорт сохраняет существующую конфигурацию
SOCKS5 и guard; в этом режиме тихий direct fallback не добавлен.

Данные чата доступны самому локальному пользователю и разрешённым локальным
процессам. Loopback не служит защитой от вредоносного ПО того же пользователя.
Логи daemon не содержат промптов, сырых исключений CLI или proxy credentials.
Настройка прокси остаётся самостоятельной локальной командой `garik proxy set`.
Перед первым импортом telemetry существующей непустой базы создаётся приватная
SQLite-копия в её backups/. Одновременный обычный CLI-чат с той же базой
отклоняется: сначала остановите daemon или используйте другую базу.

## Уточнение диагностики CLI · 13 октября

Точный исходный текст ошибки второго вызова предыдущего прогона не сохранён:
адаптер выдавал общую строку `Codex exit 0…`, временный ответ удалялся.
Из старых квитанций нельзя доказать, была ли ошибка временной, несмотря на
наличие usage и завершённого поискового инструмента.

Теперь сохраняются только безопасные категории и последовательность ошибок,
наличие turn.completed/turn.failed, код выхода, наличие и валидность ответа.
Сырой текст ошибок, URL с credentials, промпты и рассуждения не записываются.
В панели есть понятная категория, например перегрузка модели.

Исправлен узкий случай восстановления: явное `Reconnecting… N/M` перед
успешным turn.completed больше не отбрасывает валидное решение, если exit=0,
нет turn.failed, неизвестных ошибок или ошибок после завершения.
Отсутствие ответа, невалидный JSON, terminal failure и неизвестные ошибки
по-прежнему отклоняются; восстановление не запускает новый запрос модели.
Семантика проверена synthetic CLI, включая поиск и сохранение usage.
Схема событий и обработчик upstream:
[exec events](https://raw.githubusercontent.com/openai/codex/main/codex-rs/exec/src/exec_events.rs),
[JSONL processor](https://raw.githubusercontent.com/openai/codex/main/codex-rs/exec/src/event_processor_with_jsonl_output.rs).
Текущий upstream не доказывает точный текст события в прежнем alpha-прогоне.

Повтор той же разрешённой реплики из отдельной тестовой базы потратил ещё
одну попытку (всего 3 из разрешённых 6): error + turn.failed, категория capacity,
exit=1, без turn.completed и файла ответа. Это подтверждённая перегрузка
сервиса; usage отсутствует и не считается нулём. Повторных запросов при
перегрузке не делали. Daemon остановлен. Причина первоначального второго
сбоя остаётся неизвестной; успешный реальный поиск после правки не доказан.

По просьбе автора новый запуск Гарика закреплён на gpt-6.1-sol / medium.
Первые три проверочных вызова выполнялись с прежним low; результат следующего повтора на medium приведён ниже.
`garik panel` явно вызывает Microsoft Edge, не браузер по умолчанию.
Для пользовательского просмотра можно выполнить `garik daemon start`
и вручную открыть http://127.0.0.1:8765 в Edge. Headless повторно не запускается.

Полная регрессия этой правки: 99 тестов / 25.670 с, затем повтор затронутого
адаптера после ужесточения распознавания префикса. Проверки сборки промпта
(9), tools/check.py, JS syntax и git diff --check также прошли.

## Остановка и проверка расхода · 13 октября

Кнопка **«Остановить демон»** выделена в верхней части панели. После
подтверждения повторное нажатие и отправка сообщений блокируются. Итоговое
состояние «Демон остановлен» появляется по квитанции сервера: модельный
исполнитель закрыт, отмена и известный usage сохранены, сессия завершена в БД.
Квитанция содержит последний снимок чата и счётчиков. Далее закрывается HTTP.
Панель сохраняет этот снимок на экране; черновик хранится в sessionStorage
данной вкладки с привязкой к базе, неподтверждённая отправка сохраняет свой ID.
Потеря ответа сама по себе не доказывает остановку: показывается предложение
проверить `garik daemon status`. Новый экземпляр демона снимает блокировку.
Старая версия сервера подтверждает только принятие команды — новый интерфейс
не выдаёт эту квитанцию за подтверждение завершения.

Обновление HTML/JS видно после перезагрузки вкладки. Изменения Python
(итоговая квитанция и удаление дублей контекста) вступают в силу при следующем
запуске демона. Рабочий пользовательский процесс при разработке не останавливали.

Проверка сохранённых квитанций рабочей базы выполнена только через read-only
SQLite, без новых модельных вызовов и без вывода переписки. На момент проверки
семь попыток текущего запуска действительно дали **131884 input+output**:
пять последних сообщений — 92715, предшествующее пробуждение и его поисковый
этап — 39169. Для пяти сообщений было по одной попытке:

| Вход | Выход | Cached input | Reasoning внутри выхода |
| ---: | ---: | ---: | ---: |
| 18148 | 354 | 0 | 226 |
| 18116 | 429 | 0 | 110 |
| 18163 | 485 | 0 | 213 |
| 18042 | 296 | 0 | 76 |
| 18203 | 479 | 0 | 192 |

Все пять — `gpt-6.1-sol`; заданное усилие адаптера — `medium`.
Каждой соответствует одна квитанция usage, её значения совпадают с итогом
хода. Нулевой cached input присутствует в квитанциях, это не подстановка
вместо отсутствующего поля. Отсутствующее/некорректное поле сохраняется как
`null` и отображается «—». При неполном покрытии суммарное поле теперь имеет
«≥», даже когда известная часть равна нулю. Итог складывает только input и
output; cached и reasoning повторно не прибавляются. Повторные и накопительные
usage одного вызова заменяют его известные значения, не складываются друг
с другом. Архивный итог хода не складывается с включёнными попытками.

Причина большого входа видна в адаптере: каждый этап запускает новый
`codex exec --ephemeral` в отдельной временной рабочей папке. Продолжение
сессии (`resume`) не используется. Полностью собираются личность с лексикой,
контракт исполнителя, состояние, история, найденная память, сведения о занятиях.
В последнем запросе локальная оценка составила ~10687 токенов: личность и
лексика ~5080, контракт ~1208, найденная память ~3065, история ~527.
Это **оценка другим токенизатором**, а не разбивка измеренных 18148: собственные
инструкции/схема/инструменты CLI вне оценки. Разницу нельзя объявлять точно
измеренным служебным объёмом. Usage поисковой попытки также может включать
несколько внутренних обращений модели с результатами инструментов.

Исправлен один ненужный повтор: фрагменты эпизода исключаются из найденной
памяти, если их исходный текст уже полностью представлен в включённой истории.
Урезанная или вытесненная история, воспоминания из другого разговора,
самостоятельные факты/связи/дневник остаются. Освободившийся бюджет не заполняется
новыми записями. Архив и память в БД не удаляются. Счётчик удалённых повторов
попадает в следующий отчёт контекста. Фактическую экономию модельных токенов
после изменения пока не измеряли.

Дальнейший вариант для отдельного согласования: стабильная рабочая папка и
постоянный префикс инструкций, затем эксперимент с продолжением сессии и
передачей только изменений состояния. Нужно отдельно проверить ограничения
инструментов, отмену, восстановление и границы памяти. Сам `resume` не делает
предыдущий контекст бесплатным. Причина нулевого кеша в этих квитанциях не
установлена; гарантировать кеширование или конкретную экономию нельзя.

Проверки: 103 Python-теста, включая остановку во время генерации, сохранение
квитанции, чат/usage после нового запуска, cumulative usage, пропущенный/нулевой
cache и безопасное удаление дублей. Семь offline JS-тестов контроллера проверяют
повторное нажатие, финальный снимок, запоздавший снимок, потерю ответа,
старую версию сервера, новый экземпляр, восстановление черновика, сохранение
неподтверждённой отправки и частичный кеш. Node используется
только для тестов, новых зависимостей нет. Визуальная проверка в Edge для этой
правки не выполнена: Computer Use ранее не соединялся; headless не повторяли.
