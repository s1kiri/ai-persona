# Постоянные диалоги Codex

Актуальные изменения от 14 октября: [непрерывная жизнь, delta-контекст и обратимый reset](runtime-continuity-2026-10-14.md). Они уточняют прежние значения лимитов и описание передачи контекста ниже.

Исполнитель использует собственный дочерний `codex app-server --listen stdio://`
на проверенной версии 0.162.0-alpha.17.2. CLI chat/step/watch и daemon используют
один адаптер; `doctor` и явный `proxy health --codex` остаются отдельными пробами.
Модель по умолчанию — `gpt-6.1-sol`, effort — `medium`.

Полная личность и контракт передаются при создании диалога. В последующих ходах
добавляются новая реплика, изменившиеся записи истории/памяти и актуальные
снимки состояния, целей, занятий и разрешений аудитории. Предложения модели
не считаются доставленными сообщениями: только квитанции SQLite подтверждают
доставку. У разных людей, разговоров, регистров и самостоятельных пробуждений
разные диалоги. Изменение личности создаёт новую область диалога.

Это сокращает повторную передачу от Python к app-server и позволяет сохранять
диалог и соединение. Это **не гарантия** отправки только новых токенов от Codex
к модели, постоянного KV-кеша или меньшей стоимости каждого ответа. История
остаётся частью модельного входа. Cached input измеряется по квитанции Codex,
отсутствующие поля не выдумываются. Локальная оценка сборки промпта не является
измерением входа модели; `session.input.sent_chars` показывает именно новое
обновление от хоста. Cache-write ноль в app-server может быть значением
протокола по умолчанию, а не отдельной квитанцией провайдера.

## Исследование

Основной диалог просит поиск коротким `web_query`. Хост создаёт отдельный
research thread в том же app-server. Он получает вопрос, цель, время и
идентификаторы задачи/события; личность, память и переписка ему не передаются.
Результат ограничен восемью фактами со ссылками и четырьмя оговорками. Он
возвращается отдельным host update в прежний основной диалог, не транскриптом.
Источники считаются недоверенными данными. Финальный ответ может ссылаться
только на URLs из полученного результата; наличие квитанции поиска не доказывает
истинность источника. Каждое новое событие/вопрос создаёт отдельную задачу.
Автономных уточняющих исследовательских циклов сейчас нет.

Полный путь занимает три хода: решение Гарика, исследование, продолжение Гарика.
Каждый входит в лимит сессии. Исследование не создаёт outbox и не меняет память.
Новая реплика отменяет устаревший результат до его применения.

## Пределы и изоляция

Не загружаются пользовательские shell, hooks, plugins, apps и multi-agent tools.
Унаследованные MCP-серверы отключаются точечными настройками до thread/start.
Необычные идентификаторы MCP, которые эта версия CLI не позволяет безопасно
переопределить, вызывают отказ. Сторонние инструкции и переопределение встроенного
провайдера также вызывают отказ. Глобальные настройки пользователя не меняются.

Остаточный каталог sol содержит code-mode wrapper, часы, MCP resource helpers,
async input и apply_patch. Это не пустой набор инструментов. Shell отсутствует;
запись apply_patch запрещает read-only sandbox; host requests отклоняются.
Один только поток событий app-server не показывает каждую запрещённую попытку,
поэтому он не заменяет sandbox. Новые зависимости не установлены.

Встроенный `features.rollout_budget` ограничивает внутренний цикл Codex:
uncached input + output, по умолчанию 500000 для основного диалога и максимум
50000 для исследовательского. У провайдера могут быть собственные budget units.
Дополнительно действуют wall timeout, предел потока 2 MB и ограничения известных
input+output в хосте. Это не точный предел числа HTTP-запросов: один ход с
инструментами может включать несколько обращений к модели, а уже начатое
обращение может превысить порог. Лимит инструментов также не отменяет уже
начатую серверную операцию.

Автоматическая compaction выключена, чтобы не добавлять скрытый модельный этап.
Очень длинный диалог может достичь контекстного окна и остановиться с ошибкой;
бесконечная жизнь одного thread этим изменением не обеспечена.

При включённом SOCKS весь дочерний app-server находится под тем же сетевым
Seatbelt guard, что прежний адаптер. Мост живёт вместе с процессом, простаивающие
туннели сохраняются, при остановке закрываются. Ошибка не вызывает direct fallback.
Это ограничение дочернего транспорта, не утверждение об отсутствии другого
трафика на Mac. Пароль остаётся внутри локального Keychain/моста.

## Восстановление

В приватном каталоге данных: `codex-session/sessions.json` (0600), рабочая папка,
состояние и журналы Codex; весь родительский каталог должен оставаться приватным.
Эти данные могут содержать разговоры и не входят в Git.
SQLite хранит принятую стадию события; перед turn/start fsync сохраняет намерение,
идентификатор сообщения и попытки. После ответа сохраняется квитанция, затем
SQLite принимает стадию, затем адаптер подтверждает её принятие.

После сбоя нет автоматического повторного inference. Явный retry использует
готовую квитанцию либо сверяет thread/read с известным turn ID. Если принятие
неизвестно или у завершённого исследования потеряна квитанция инструмента,
повтор блокируется. Новое намерение пользователя может продолжить работу в новом
диалоге, не применяя старое предложение. Outbox сохраняет прежние UUID и квитанции.
При переносе для продолжения thread нужны **и база, и каталог codex-session**;
одной SQLite-копии недостаточно для продолжения сессии Codex.

## Повторить проверки без модели

```sh
.venv/bin/python -m unittest discover -s tests
.venv/bin/python tools/check_codex_session.py
.venv/bin/python tools/check_codex_isolation.py
```

Две последние проверки используют установленный Codex, синтетический Responses
на localhost и временные данные. Seatbelt запрещает другой исходящий TCP.
Они не используют реальный прокси/Keychain и не вызывают внешнюю модель.
Проверяются постоянный thread и restart, отдельный каталог инструментов поиска,
отказ неподтверждённого поиска, реальный отказ записи, отсутствующий shell,
отключение MCP, встроенная остановка цикла после двух mock-запросов и deadline.

Обычный ручной запуск после проверки:

```sh
./start-garik.command proxy status
./start-garik.command daemon start --no-autonomy --max-calls 6
./start-garik.command panel
./start-garik.command daemon stop
```

`panel` сам запускает daemon при его отсутствии. Обновление кода не запускает
рабочий процесс автоматически и не меняет настройки сна или автозапуска.

## Фактическая проверка 13 октября 2026

125 Python-тестов, 7 тестов панели и 9 проверок сборки личности прошли.
Два installed-CLI mock-прогона: 4 синтетических запроса для сессии/перезапуска/
разделения поиска и 7 для отрицательных сценариев (write 2, shell 2, loop 2,
stall 1). В отрицательных сценариях все дочерние процессы завершены, canary-файлы
не появились, MCP не запустился. Начало webSearch с `action: null` теперь допустимо.

Реальный тест ограничен шестью ходами на отдельной приватной базе, через ранее
настроенный SOCKS. Рабочий daemon не запускался. В таблице — квитанции Codex;
cached входит в input, reasoning входит в output и повторно не суммируется.

| Ход | Проверка | Input | Output | Cached input | Первый текст / завершение, с |
|---|---|---:|---:|---:|---:|
| 1 | Приветствие | 8706 | 116 | 0 | 12,650 / 15,829 |
| 2 | Новая реплика в том же процессе | 9227 | 171 | 8576 | 4,411 / 9,412 |
| 3 | Перезапуск, прежний thread ID | 9981 | 92 | 0 | 13,606 / 16,056 |
| 4 | Просьба погуглить | 10493 | 347 | 9856 | 13,309 / 14,438 |
| 5 | Отдельное исследование, ошибка обработчика | — | — | — | — |
| 6 | Отдельное исследование после исправления | 14906 | 152 | 6272 | 37,851 / 40,344 |

После перезапуска Гарик вспомнил тестовое слово «фонарь». Второй ход не запускал
новый app-server (startup 0 ms) и не добавлял CONNECT к уже открытым соединениям.
Кеш после перезапуска был нулевым: сохранённый thread ID не гарантирует cache hit.
Эти короткие сцены нельзя напрямую сравнивать со старыми большими разговорами.

Ход 4 не запросил исследование: Гарик ответил по времени среды и ошибочно сказал,
что погуглить не может. Исправлен контракт хоста: доступность JSON web_query
теперь явно отделена от наличия прямого web-инструмента у основного диалога.
Автоматический выбор web_query после этой правки **не проверен реальным ходом**.

Для оставшихся двух ходов исследовательский этап был явно задан тестовым хостом,
а не выбран Гариком; это не выдаётся за автономное решение персонажа. Ход 5
обнаружил `action: null` в событии начала поиска; обработчик остановил процесс,
результат не применялся. Usage этой попытки неизвестен, не нулевой. После исправления
ход 6 завершил один native web call и вернул факт с источником `https://time.is/UTC`
о дате 13 октября 2026 года. Подтверждена структурированная квитанция поиска и
ограниченный результат, но достоверность содержимого страницы отдельно не аудировалась.

Бюджет шести ходов исчерпан. Полный реальный маршрут «Гарик выбрал исследование →
research → Гарик ответил» после исправлений не выполнен; передача результата,
сохранение основного thread, отмена устаревшего результата и обе границы сбоя
проверены синтетическими тестами. Это оставшаяся граница проверки, не скрытый
успешный end-to-end. Точные тестовые переписки и receipts находятся только в
игнорируемой `.local/validation/app-server-migration/`.
