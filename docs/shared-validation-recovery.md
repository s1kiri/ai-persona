# Источники и квота историй общего мира

17 октября выявлены два независимых отказа уже завершённых модельных ответов.
Оба сохранены вместе с usage; повторного вызова для их восстановления нет.

## Авторские события как причины

`author_world_facts` содержит применённые события с устойчивыми ID. Эти ID
добавляются в `brief.cause_ids` при подготовке общего цикла. Мир вправе
использовать их как причины продолжения. Несуществующее, неприменённое или
не переданное событие по-прежнему не является причинной квитанцией.

Это право ведущего мира, не автоматическое знание героя. Его история содержит
только собственное наблюдение; `unaware` не получает скрытого содержания
новости или самого авторского запроса.

## Квота для каждого участника

Ползунок `max_threads` ограничивает незакрытые истории каждого управляемого
героя. Частные истории Гарика не занимают места Аркадия. Общая история
учитывается у всех участников из `visible_to`. `open_slots` и список наступивших
сроков режиссёра рассчитываются для выбранного героя.

При снижении лимита уже начатые истории остаются: нельзя добавлять сверх
прежнего числа или текущего лимита данного героя. Истории без наблюдателей
имеют отдельный такой же конечный лимит. Закрытые истории и старые финалы
не удаляются и не переписываются ради освобождения места.

## Разбор сохранённого результата

`SharedWorldStore.recover_saved_shared_stage` вызывается только явно на паузе
обоих, без активных вызовов. Принимается точный сохранённый ответ `world` или
`outcome`, отклонённый с ValueError. Все проверки результата выполняются снова.
Для старого world разрешаются только ID уже применённых событий, которые
действительно были переданы в исходном входе. Это не универсальный обход
валидации и не автоматическое повторение.

Исходные вход, отказанный ответ, ошибка, call/status/usage сохраняются.
Отдельный аудит описывает прежний цикл и основание разбора. Outcome проходит
обычное применение временного окна, позиции и наблюдаемости. Следующий этап
паркуется как held, чтобы несколько восстановленных героев продолжались
по очереди со свежей общей revision. Второй раз результат не применяется.

Проверки на временных данных покрывают отдельную/общую квоту, снижение
ползунка, закулисные истории, доступные/выдуманные авторские причины,
отсутствие утечки знания, сохранение вызова/usage/окна, откат невалидного
разбора и продолжение после изменения общей revision.
