# Подключение Telegram · 15 октября 2026

Этот документ описывает первоначальную техническую проверку. Последующий
запуск персонажа описан в [собственной жизни в Telegram](channel-life.md).

Обычный бот из BotFather подключён к локальному экрану настройки. Для него
достаточно Bot API token; `api_id` и `api_hash` пользовательского клиента не нужны.
Модель Гарика, мир и генератор фотографий на этом шаге не запускаются.

## Что работает

- Локальный ввод токена в скрытое поле, проверка `getMe` и отсутствия чужого
  webhook. Существующий webhook автоматически не удаляется.
- Поиск доступного канала по новым `channel_post` / `my_chat_member`, ручной
  выбор канала, проверка взаимной привязки обсуждения и прав администратора.
- Приём через `getUpdates`, постоянный курсор и устранение повторов. Пачка
  и следующий курсор записываются одной транзакцией. Чужие личные сообщения
  не сохраняются. Тексты сохраняются только для выбранного канала и обсуждения.
- Связь поста канала с автоматически пересланным корнем обсуждения через
  `is_automatic_forward` / `forward_origin`. Вложенные ответы сохраняют корень.
- Явная кнопка технического поста и отдельная кнопка ответа на полученный
  комментарий. Ответ отправляется через `reply_parameters.message_id` в группу
  обсуждения. Форумный `message_thread_id` для отправки не используется.
- Постоянная очередь отправок и квитанции. Повтор того же завершённого задания
  возвращает квитанцию без новой отправки; другой текст с прежним ключом
  отвергается. После обрыва/остановки неизвестная доставка не повторяется.
- В транспортном адаптере есть загрузка фотографии через `sendPhoto`.
  На этом шаге она проверена только на вымышленных квитанциях; кнопки загрузки
  и постоянного соединения с автономным генератором пока нет.

## Токен и экран

Экран привязан только к `127.0.0.1`, защищён локальной cookie, проверкой Origin,
Host и CSRF. Скрипты и стили локальные, сторонней аналитики нет. Токен не
передаётся в URL локальной страницы, состояние пульта, промпт, командную строку
или журналы. Поле очищается перед отправкой и не заполняется ответом сервера.

Токен сохраняется в игнорируемой папке подключения, в файле `bot-token.json`
с правами `0600`; папка имеет права `0700`. Это обычный локальный закрытый файл,
не шифрованное хранилище. Keychain не используется: новых запросов пароля
macOS при старте этого подключения нет. Bot API получает токен по HTTPS;
его адрес не выводится при ошибках. Переадресации HTTP запрещены.

Открытие страницы и сохранение токена не отправляют постов. Технические тексты
явно обозначены как проверка связи, а не высказывание персонажа. Никакая модель
не вызывается. После перезапуска достаточно обновить страницу: токен сохраняется,
курсор и квитанции не сбрасываются.

Запуск отдельного экрана, без изменения старого пульта мира:

```sh
.venv/bin/python -m persona_runtime.telegram_setup \
  --data-dir .local/telegram --port 8767 --background
```

Одновременное открытие той же папки вторым приёмником блокируется локальной
блокировкой. Конфликт с другим внешним получателем / webhook тоже останавливает
приём. Повторы чтения после сетевых ошибок допустимы; повторы неизвестной
отправки автоматически не выполняются.

## Фактическая проверка и исправление

Пользователь самостоятельно ввёл токен, выбрал канал и нажал отправку
технического поста. Получена квитанция `sent`; автоматически пересланный корень
обсуждения принят. Два реальных комментария привязаны к этому корню.
Идентификаторы канала, токен и точные данные остаются в `.local/`.

Первая версия ошибочно спрятала комментарии анонимного администратора, приняв
совместимого отправителя Telegram `GroupAnonymousBot` за настоящего бота.
Исправлено: `sender_chat` имеет приоритет над подставным `from`. Реальная
личность анонимного автора не угадывается. Сохранённые ошибочно скрытые
комментарии восстановлены по известному служебному ID, с отдельной отметкой
ремонта. До исправления сделана резервная копия базы; приёмник перезапущен
без сброса курсора, повторной отправки поста и нового ввода токена.

Проверены 17 офлайн-тестов транспорта/HTTP и 4 UI-теста: закрытость секрета,
защита локального сервера, права, курсор и повторы, вложенные комментарии,
анонимный администратор, восстановление, неизвестная доставка, буквальный
вывод пользовательского текста. Они не доказывают долгосрочную автономную жизнь.

## Следующий шаг

После квитанции технического ответа соединить принятый прямой голос Гарика
с реальным комментарием и его исходным постом. Затем отдельно проверить
фотографию через автономный инструмент и Bot API, после чего подключать
выбранные персонажем публикации из цикла жизни. Исторические черновики мира
автоматически в канал не выгружаются. Подключение Telegram само по себе
не включает модель, автономную публикацию или ответы читателям.

Источники: [Bot API](https://core.telegram.org/bots/api),
[получение событий](https://core.telegram.org/bots/api#getupdates),

[обсуждения канала](https://telegram.org/faq_channels#q-are-there-any-feedback-options).
