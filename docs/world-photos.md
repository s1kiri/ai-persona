# Необязательные фотографии из мира Гарика

15 октября 2026. Автор предложил проверить фотографии предметов и результатов
из прожитых сюжетов. Гарик может захотеть показать предмет и выбрать кадр,
а может обойтись без фотографии. Это дополнение к собственному каналу,
не новая норма «иллюстрировать каждый пост». Недоработка характера с примером
карты записана в локальный бэклог; она не блокирует движение к Telegram.

## Новая сцена без референса и память внешнего вида

По новому поручению автора проведён второй отдельный автономный кейс:
жареные яблочные дольки и курица из шаурмичной. В рабочей истории найден
подтверждённый outcome на minute1657: курица без соуса куплена, на тарелке
рядом яблоки, один кусочек уже попробован. В тесте воспроизведён этот
момент, до доедания; он не стал новым действием рабочей жизни.

Никаких изображений не передавалось, references=0. Гарик выбрал оба
предмета, ракурс немного сверху и собственную подпись. Его нативный
генератор создал новую фотографию еды1312×1199, получены completed,
turn/completed и квитанция файла. Ручных правок, восстановления и вызова
image_gen родительского чата не было. Проба ограничена2 вызовами без
повторов, завершена успешно. Фото и точные данные сохранены в
.local/evaluations/autonomous-apple-chicken-2026-10-15. Визуально видны
курица и обжаренные дольки с кожицей на одной тарелке, без соуса/гарнира.

Автор дополнительно уточнил: одинаковые предметы/места должны сохранять
облик между фотографиями, но каждый новый запрос должен давать новый кадр.
Например, у шаурмичной возможны фасад, другой угол, вход и интерьер.
Для этого добавлена MediaReferenceLibrary, отдельная от учёта заданий.
По постоянному ID сущности сохраняются несколько снимков с описанием
показанного вида. В библиотеку попадают явно одобренные референсы либо
изображения, для которых хост передал квитанцию поста канала. Новая
непоказанная проба сама по себе туда не записывается. Второй снимок карты
зарегистрирован по авторскому предпочтению; результат с едой пока только
тестовая картинка, не обязательный эталон следующих блюд.

Библиотека хранит собственную копию изображения и SHA256, поэтому уборка
каталога теста не уничтожит эталон. По ID объекта и участнику подбираются
до3 различных ранее показанных видов. Чужие, неизвестные и повреждённые
референсы не подаются; снимок с неизвестным сопутствующим объектом также
не раскрывается. Промпт выбора получает краткие описания прежних фото,
а генератор — сами изображения, текущую сцену и отдельно выбранный
новый ракурс. Референс задаёт идентичность, материалы и узнаваемые детали;
новый запрос задаёт кадр. Это не автоматическое восстановление точного
интерьера по одному фасаду и не разрешение фотографировать невидимое.
Новый показанный интерьер позже может стать дополнительным референсом.

Новый запрос имеет свой ID/каталог задания и запускает генерацию даже
при том же ID шаурмичной. Возврат сохранённого файла относится только
к повтору того же завершённого задания после сбоя; библиотека внешности
не является кешем готового ответа. Точное совпадение SHA256 с входным
референсом не проходит проверку нового изображения. Это ловит повтор
файла, но само по себе не доказывает новый ракурс: его соблюдение остаётся
визуальной проверкой качества генерации.

Автономный тестовый runner поддерживает --reference-library; прямой
--references сохранён для совместимости. Библиотека и передача новой
инструкции о ракурсе добавлены после успешного теста еды. Прошли7 проверок
библиотеки и7 проверок кейса: несколько видов, постоянные ID, собственные
копии, отказ на неизвестное/повреждённое, передача референса и запрет
старого файла как нового. Полная серия разных видов одного места с новой
библиотекой на модели пока не проводилась. Постоянный цикл/Telegram
к этой библиотеке и генератору ещё не подключены; рабочий мир на паузе.

## Полный автономный тест пройден

По новому прямому поручению автора выполнен отдельный тест-кейс
AutonomousPhotoCase: сцена → свободный выбор Гарика → проверенное задание →
его нативный Codex imageGeneration → файл → проверка квитанции и SHA256.
Родительский чат не вызывал image_gen, не правил промпт/изображение после
выбора и не восстанавливал файл вручную. Сценарий запускается отдельной
командой, не требует активного чата и может использоваться будущей очередью.

Гарик с принятой личностью сам выбрал show, тот же план, ракурс и подпись.
При skip исполнитель не запускает генерацию; это проверено офлайн.
Референс второго снимка подобран по постоянному ID предмета из заданного
списка. Новый генератор не получил полного дневника или авторского чата.
Сцена взята из уже прожитого вымышленного эпизода, не добавлена в рабочую
ленту. Само окно выбора было открыто тестовым исполнителем, а не спонтанным
пробуждением жизни; частоту самостоятельного желания фотографировать
этот тест не измеряет.

На живом Codex получены imageGeneration in_progress → completed,
turn/completed и usage. status=generated, native_receipt_received=true.
Кейс имеет status=passed; восстановление не использовалось. Это закрывает
прежнюю оговорку об отсутствии живого полного повторного прохода через
исправленный приёмник. Готовый PNG1448×1086 визуально проверен; карта,
легенда, год, кварталы и бумага сохраняются, кадр новый. Существенные
географические детали не внесены из изображения в канон.

Этот новый явно порученный тест ограничен2 вызовами:1 выбор,1 рендер,
без повторов. Прежняя серия112/112 остаётся закрытой. Повторный запуск
завершённого кейса отдельным процессом вернул сохранённый результат:
0 новых модельных вызовов,0 новых изображений, исходные файлы неизменны.

Точный результат, источники, обе квитанции и операционный trace без текстов
скрытого рассуждения сохранены в
.local/evaluations/autonomous-photo-case-2026-10-15. Новый image-generation
ID:exec-0e4d4aed-0a88-4640-83a2-fa98a685cf56. Картинка — photo.png;
case.json содержит выбор и итог; replay-check.json — проверку повторного
запуска без расходов. Фото показано автору и не опубликовано наружу.

Запуск аналогичного нового теста на отдельной сцене:

Повтор той же директории не генерирует заново. Неуспешный/начатый кейс
требует явного восстановления. Кейс не проходит на текстовом обещании,
неверном хеше или только восстановленном файле без нативной квитанции.
Прошли113 проверок мира и5 проверок нового автономного кейса. Последние
проверяют свободный отказ, недоступный предмет, полный результат, защиту
от повтора и неприемлемость восстановления вместо полного live-прохода.

Нативный генератор и самостоятельный тестовый исполнитель проверены.
Постоянный жизненный цикл мира и отправка вложений в Telegram пока не
подключены; эту границу успех кейса не отменяет. Рабочая база сохранена.

## Уточнение: нативный генератор отдельного Codex-процесса

Автор справедливо указал, что первая проба не проверяла подключение к его
самостоятельному исполнителю. Она проверяла выбор фото и генератор текущего
чата. После уточнения проверен именно отдельный headless Codex app-server
версии0.162.0-alpha.17.2 с тем же прежним логином/прокси, без участия
image_gen родительского чата, нового API-ключа и Image API.

В установленной версии features.image_generation — stable. Экспортированный
самой этой версией протокол содержит imageGeneration с result, savedPath,
status, revisedPrompt и failure. Для отдельного CodexImageBackend включены
только image_generation и требуемый code_mode_host; остальные инструменты
остались выключены. Обычные персонажные/мировые вызовы не получили новых
прав. Генератор получает уже проверенное узкое задание, а не личность или
переписку. Существующий выбор show/skip остаётся до него.

Одна реальная попытка создала PNG1448×1086,2777140 байт, в каталоге нового
нативного потока. Второй снимок из предыдущей пробы использован как
предпочтительный референс по отзыву автора. Картинка отличается от референса
и визуально сохраняет его карту, кварталы, год, легенду, бумагу и стол.
Путь и принадлежность потоку сверены с журналом отдельного исполнителя.
Снимок восстановлен в локальный каталог опыта без повторной генерации.

Приём RPC в первой попытке оборвался сообщением об окончании сессии или
превышении лимита вывода. Прежний текстовый приёмник ограничивал сообщение
двумя миллионами символов; такое PNG в base64 превышает этот предел.
Локальная проверка воспроизводит отказ старого лимита и успешный приём
увеличенного. Для процесса изображений введён предел60 миллионов символов,
для обычных текстовых процессов сохранён старый. Первоначальный запущенный
процесс ещё использовал старый приёмник. Утверждать полный успешный
повтор нового приёмника на живой модели пока нельзя: его не было.

Восстановление различает готовый локальный файл и квитанцию завершения
нативного вызова. У результата status=recovered, generated=true,
native_receipt_received=false, turn_completion=unknown. Проверены собственный
ID потока, единственность PNG в его каталоге, заголовок/размеры/конец файла;
не угадывается «самая новая картинка» из других чатов. Usage этой попытки
не получен и не объявляется нулевым. Модель не вызывалась повторно.
Старый общий счёт попыток теперь112/112. Автоматического нового бюджета нет.

До отправки задания записывается marker с ID потока. Новый запуск не
повторяет такой запрос незаметно: требуется восстановление или явное
решение о новой попытке. Отказ, второй image-вызов и посторонние операции
не выдаются за успешное фото. У результата всегда published=false.

Это готовый нативный адаптер для будущей очереди: заявка Гарика → отдельный
CodexImageBackend.render → файл и метаданные → вложение в выбранный пост.
Для принятого кадра можно передать references как localImage. Повторную
генерацию/правку выбирает персонаж/хост; она не нужна к каждому сообщению.
Сейчас вызов на отдельном процессе проверен, но постоянная очередь,
встраивание в WorldSession и доставка фото в Telegram ещё не подключены.
Точные данные опыта — .local/evaluations/native-codex-image-2026-10-15.

Прошли11 новых офлайн-проверок нативного адаптера, включая реальный локальный
процесс с крупным сообщением, отсутствие повтора, восстановление собственного
файла и отказ на чужой/неоднозначный каталог. Отдельно прошли24 проверки
обычного AppServerBackend. Это не нагрузочная проверка долгой автономной
публикации. Рабочий daemon, мир, личность и словари не переключались.

Официальная инструкция описывает встроенную генерацию Codex с расходом
лимитов плана; установленный локальный протокол и реальная попытка уточняют
доступность именно нашего маршрута.
[Встроенная генерация](https://learn.chatgpt.com/docs/image-generation),
[App-server и экспорт схемы](https://learn.chatgpt.com/docs/app-server).
Ограничения preview Sign in with ChatGPT не следует смешивать с нативным
инструментом уже настроенного Codex: поддержка hosted image_generation
на том отдельном API-маршруте не заявлена.
[Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

## Выполненная проба

В отдельном текстовом вызове принятая личность получила последний уже
состоявшийся момент с картой: план1988 года куплен, развёрнут на кухонном
столе, сгиб надорван, существующие кварталы закрашены, проектируемые
обозначены контуром. Магазин и отдельные здания на плане не отмечены.
Из контекста исключены скрытые заметки мира и сведения других участников.

Модель сама выбрала show, предмет и ракурс: сверху над столом, знакомая
дорога, различие кварталов, легенда и сгибы. Прямого поручения «покажи
именно карту» внутри этого запроса не было. Само окно выбора инструмента
открыл исполнитель: это проверка выбора, не самостоятельное пробуждение.
Во втором, вымышленном контрольном случае доступных предметов не было и
было задано желание пока не трогать канал; модель выбрала skip, задания
генератору не появилось. Два ответа не измеряют естественную частоту фото.

Текстовая часть:2/2 успешно, gpt-6.1-sol, medium, общий расход прежней
серии111/112, осталась1 попытка. Принятый промпт не менялся. Генерация
выполнена отдельно встроенным image_gen в текущем чате: одна новая
картинка и одна точечная правка. Это отдельный расход генератора изображений,
не ещё один вызов текстового WorldBackend. Точный расход изображения
инструмент не сообщил. Первая версия показала отдельные здания вопреки
текстовому состоянию; правка заменила их целыми кварталами и добавила
мелкие подписи улиц, сохранив ракурс, бумагу, стол, год и легенду.

Финальный снимок, оба промпта, выбор персонажа и квитанции сохранены
локально в .local/world-media/photo-map-2026-10-15 и
.local/evaluations/world-photo-2026-10-15. Картинка показана автору;
она не опубликована в Telegram и не добавлена задним числом в старую ленту.
Рабочая база мира не изменялась. Названия улиц, реки, геометрия карты и
цвет стола — сгенерированные визуальные детали; автор ещё не утвердил их
как постоянный лор. Изображение не доказывает произошедшее событие.

## Что подключено и где граница

Добавлен небольшой проверяемый прототип: подготовка доступного фотографу
контекста, необязательный выбор show/skip, проверка источников и предмета,
сборка задания генератору. Отказ даёт None, не скрытую генерацию. Запрос
имеет состояние requested, generated=false, published=false. Только
реальный результат генератора может стать готовым медиафайлом.

В первой пробе этот прототип был выполнен исполнителем текущего чата. Встроенный
инструмент чата нельзя считать автоматически доступным отдельному процессу
Гарика: нынешний WorldBackend отключает image_generation и отвергает
операции кроме текста. Он не был незаметно переведён в другой режим.
Полностью автономный исполнитель изображений и вложения в Telegram
первой пробой не были подключены. Нативная проверка описана выше. Новых ключей, тарифов и внешних публикаций нет.

## Как включить в автономный канал

К решению о записи добавляется необязательный photo-запрос. Он может
сопровождать текст, быть отдельным снимком или отсутствовать. Хост проверяет
доступность предмета и момента и ставит запрос в отдельную очередь медиа.
Текст поста не нужно сочинять заново ради картинки. Медиа-работник получает
узкий пакет сцены, не весь дневник и промпт личности; после реального
результата сохраняет файл, идентификатор предмета, промпт и квитанцию.
Ошибку или незавершённую генерацию нельзя выдавать за готовую фотографию.
Повтор после сбоя должен быть явным: не дублировать дорогую генерацию
при восстановлении приложения. Изображения хранятся отдельно от фактов мира.

Официальный Responses API позволяет предоставить image_generation как
инструмент, который модель выбирает сама; для отдельного подготовленного
задания есть Image API. Это два возможных провайдера очереди, не обязательная
смена личности. Использование API требует отдельно настроенного API-доступа;
авторизация Codex не была переиспользована как API-ключ.
[Image generation tool](https://developers.openai.com/api/docs/guides/tools-image-generation),
[Image API и Responses API](https://developers.openai.com/api/docs/guides/image-generation).

В существующей обвязке Codex другой возможный интерфейс — узкий инструмент
request_world_photo через dynamicTools, а исполняет его хост. App-server
документирует экспериментальный вызов item/tool/call и возврат результата;
доступность конкретного автономного генератора этим не подтверждается.
[Codex App Server](https://learn.chatgpt.com/docs/app-server).
Встроенная генерация текущего приложения подтверждена этой пробой;
[официальная инструкция](https://learn.chatgpt.com/docs/image-generation)
отдельно направляет программные интеграции к Image API.

Для продолжений одного предмета сохранять одобренный кадр и визуальные
инварианты под его постоянным ID. Следующее изображение строить с этим
референсом, меняя только произошедшее. Референс из этой пробы сохранён,
но автоматический поиск/подстановка референсов пока не реализованы.
Новые существенные визуальные факты не вносить в лор просто потому,
что генератор их дорисовал. Для снимков самого Гарика понадобится также
утверждённая внешность; в пробе были только предмет и стол, без рук/лица.

## Как задавать промпт

Основа — момент и видимый предмет, а не весь пост с его преувеличениями.
Пакет содержит состояние, материал, повреждения, положение и то, чего
в кадре не должно появиться по лору. После него идёт выбранный Гарьком
ракурс. Отдельно задаются обычная камера телефона, доступный свет,
фактура бумаги и бытовая композиция без студийной постановки. Подпись
персонажа хранится отдельно: не печатать её поверх фотографии.

Такое описание следует рекомендации OpenAI задавать фотографию через
конкретный ракурс, свет, материалы и естественные несовершенства.
[Рекомендации по естественной фотографии](https://developers.openai.com/cookbook/examples/multimodal/image-gen-1.5-prompting_guide).
Сама картинка всё равно нуждается в проверке: точный мелкий текст и
сохранение внешнего вида между генерациями имеют ограничения.
[Ограничения генерации изображений](https://developers.openai.com/api/docs/guides/image-generation#limitations).
